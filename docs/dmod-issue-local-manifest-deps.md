# dmod Issue: dmf-get silently ignores missing dependencies when using a local manifest

> This document describes a bug found in `dmf-get` (part of the `dmod` repository)
> while investigating the local module build workflow in `dmod-boot`.
> It is intended to be used as a GitHub issue description for the `dmod` repository.

---

## Summary

When `dmf-get` is called with a local manifest (`-m manifest-local.dmm`) that only contains the
locally-built module, the dependencies of that module are silently **not downloaded** and
`dmf-get` **exits with code 0** (success), causing downstream build steps to proceed as if
everything is fine.

## Steps to Reproduce

1. Build a DMOD module locally (e.g. `dmgpio`):
   ```bash
   git clone https://github.com/choco-technologies/dmgpio
   cd dmgpio
   mkdir build && cd build
   cmake ..
   cmake --build .
   ```
   This produces `build/packages/manifest-local.dmm` — a local manifest containing only
   the `dmgpio` module (pointing to the locally-built ZIP/DMF file).

2. Use this local manifest with `dmf-get` to download `dmgpio`:
   ```bash
   dmf-get dmgpio -m ~/dmgpio/build/packages/manifest-local.dmm -o ./dmf --type dmf
   ```

3. Observe:
   - `dmgpio.dmf` **is** downloaded (it is in the local manifest).
   - The dependencies of `dmgpio` (`dmclk_port`, `dmini`, `dmhaman`) are **not** downloaded
     (they are **not** in the local manifest — they exist only in the remote registry).
   - `dmf-get` exits with **code 0**, reporting success.

## Expected Behavior

`dmf-get` should exit with a **non-zero exit code** and print a clear error message listing
which dependency modules could not be resolved from the provided manifest.

Example expected output:
```
Downloading dmgpio... OK
Resolving dependencies of dmgpio...
  ERROR: Module 'dmclk_port' not found in manifest ~/dmgpio/build/packages/manifest-local.dmm
  ERROR: Module 'dmini' not found in manifest ~/dmgpio/build/packages/manifest-local.dmm
  ERROR: Module 'dmhaman' not found in manifest ~/dmgpio/build/packages/manifest-local.dmm
Failed to download all required dependencies. Exit code: 1
```

## Actual Behavior

`dmf-get` exits with **code 0** after downloading only `dmgpio.dmf`. The dependency
modules `dmclk_port`, `dmini`, and `dmhaman` are silently skipped with no error output.

## Impact

This causes silent failures in higher-level build systems (e.g. `dmod-boot`):

- The cmake build does not fail because `dmf-get` reports success.
- The resulting DMP package contains only `dmgpio.dmf` without its required dependencies.
- The firmware boots and loads `dmgpio`, which then immediately fails at runtime because
  its dependencies are missing — a difficult-to-diagnose error.

## Root Cause

`dmf-get` reads the required modules from the downloaded `.dmf` file metadata
(`Dmod_ReadRequiredModules()`), then attempts to resolve each dependency from the
manifest provided via `-m`. When a dependency is not found in the given manifest,
the failure is ignored and `dmf-get` exits 0.

## Proposed Fix

One or more of the following:

1. **Exit with non-zero when any required dependency cannot be resolved** from the
   provided manifest(s).

2. **Support a fallback manifest** (e.g. `--fallback-manifest <url>`): if a dependency
   is not found in the primary manifest, look it up in the fallback. This enables the
   local build workflow where the primary manifest is local (for the module under
   development) and the fallback is the remote registry (for its dependencies).

3. **In dry-run mode**, report which modules would be downloaded and which are missing,
   to allow scripts to verify completeness before performing the actual download.

## Workaround

Use a `.dmd` (dependencies file) that explicitly lists all required modules with their
correct sources, instead of relying only on the `-m` manifest flag and automatic
dependency resolution.

When building `dmod-boot` with a locally-built module, pass the generated `.dmd` file
via `DMBOOT_EXTRA_FLASH_DMD_FILES`:

```bash
cmake .. \
  -DDMBOOT_EXTRA_FLASH_DMD_FILES=~/dmgpio/build/dmf/dmgpio.dmd \
  -DDMBOOT_MANIFEST_URL=~/dmgpio/build/packages/manifest-local.dmm \
  -DDMBOOT_MAIN_MODULE=dmgpio
```

The `dmgpio.dmd` file (generated by `todmd` during the `dmgpio` build) contains
dependency entries with both local and remote manifest sources, so `dmf-get -d dmgpio.dmd`
correctly downloads all required modules.
